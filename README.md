# corridor-circuits

[![CI](https://github.com/Sconce-Labs/corridor-circuits/actions/workflows/ci.yml/badge.svg)](https://github.com/Sconce-Labs/corridor-circuits/actions/workflows/ci.yml)

`corridor_eligibility` — the Noir circuit a holder runs client-side to prove
they may enter a **Corridor** payment corridor, without revealing who they are.

- Product + architecture: **[Sconce-Labs/corridor](https://github.com/Sconce-Labs/corridor)**
- Soroban contracts + the ABI source of truth: **[Sconce-Labs/corridor-contracts](https://github.com/Sconce-Labs/corridor-contracts)** ([`ABI.md`](https://github.com/Sconce-Labs/corridor-contracts/blob/main/ABI.md))
- Client SDK: **[Sconce-Labs/corridor-sdk](https://github.com/Sconce-Labs/corridor-sdk)**

## What it proves

*"I hold an unexpired issuer-signed statement of tier ≥ N, whose credential
epoch is ≥ this corridor's floor, from an issuer identified by `issuer_id`, and
here is a per-corridor nullifier that can't be linked to my other corridors."*

The design is **Option B** (issuer-signed statements — no Merkle accumulator);
see [corridor/docs/CREDENTIAL_ACCUMULATOR.md](https://github.com/Sconce-Labs/corridor/blob/main/docs/CREDENTIAL_ACCUMULATOR.md).
The constraints are walked through in [`docs/CIRCUIT.md`](./docs/CIRCUIT.md);
the code is in [`corridor_eligibility/src/eligibility.nr`](./corridor_eligibility/src/eligibility.nr).

## Modules

| File | Role |
|------|------|
| `eligibility.nr` | `Public` / `Witness` structs + `check()` + tests (all failure modes) |
| `eligibility/fixture.nr` | `good()` — a valid witness with a real SDK-generated Grumpkin Schnorr signature |
| `tags.nr` | `DisclosureTag` constants (mirrors the SDK) |
| `conformance.nr` | the pinned Poseidon2 vector |
| `main.nr` | the `pub` I/O adapter |

Signature verification comes from `noir-lang/schnorr` v0.4.0 (Grumpkin, the
BN254-embedded curve — no non-native field arithmetic).

## Public-input ABI (9 inputs)

The order of `pub` parameters in `main` is a contract with `corridor-contracts`
(`crates/corridor_types`, the `PI_*` constants):

| idx | name | type | | idx | name | type |
|----:|------|------|-|----:|------|------|
| 0 | `corridor_id` | Field | | 5 | `issuer_id` | Field |
| 1 | `min_tier` | u32 | | 6 | `min_cred_epoch` | u64 |
| 2 | `now` | u64 | | 7 | `auditor_pubkey` | Field |
| 3 | `nullifier` | Field | | 8 | `auditor_blob` | Field |
| 4 | `disclosed_tag` | u32 | | | | |

**Change one side → change both, in matching PRs, and update `ABI.md`.**

## Build

```bash
noirup --version 1.0.0-beta.26
cd corridor_eligibility
nargo check
nargo test                             # 18 tests
nargo execute                          # solves the committed Prover.toml
nargo info                             # gate count — 73 ACIR opcodes
```

`Prover.toml` + `src/eligibility/fixture.nr` are generated by `corridor-sdk`
(`npm run gen-fixture -- --write`) and carry a real signature — see
[`corridor_eligibility/FIXTURES.md`](./corridor_eligibility/FIXTURES.md).

## Poseidon2 conformance

`poseidon2([1, 2]) == 0x038682aa1cb5ae4e0a3f13da432a95c77c5c111f6f030faf9cad641ce1ed7383`
is asserted here (`conformance.nr`), in `corridor-sdk` (`@zkpassport/poseidon2`),
and in `corridor-contracts` (`rs-soroban-poseidon`). All three agree. Under
Option B `corridor.compact` does no hash-critical work, so Midnight is not on
this list.

**Schnorr conformance:** `corridor-sdk/src/schnorr.ts` is pinned to
`noir-lang/schnorr` v0.4.0's test vector, and CI's `nargo execute` solves a
fixture the SDK signed — so the SDK signer and this circuit's verifier agree.

## Known gaps

- `auditor_blob` is a hiding commitment, not encryption yet — M7
  ([#3](https://github.com/Sconce-Labs/corridor-circuits/issues/3)).
- `bb prove`/`verify` in CI is best-effort (warns, doesn't fail) until a `bb`
  release with a published mapping for beta.26 exists
  ([#1](https://github.com/Sconce-Labs/corridor-circuits/issues/1)).
- Targeted single-credential revocation (an on-Stellar IMT) is designed but
  deferred; short expiry + `min_cred_epoch` cover the pilot.
