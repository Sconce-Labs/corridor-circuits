# The committed `Prover.toml` + `src/eligibility/fixture.nr`

Both are **valid** witnesses carrying a real Grumpkin Schnorr signature —
`nargo execute` solves every constraint against `Prover.toml` in CI on every
push, and `src/eligibility/fixture.nr` (`good()`) drives the `nargo test`
cases. They are generated by `corridor-sdk`, which owns the signer.

## Regenerate

From `corridor-sdk` (checked out as a sibling of this repo):

```bash
cd ../corridor-sdk
npm run gen-fixture -- --write
```

This writes both `Prover.toml` and `src/eligibility/fixture.nr` here. Without
`--write` it prints them to stdout (that's the SDK CI signing smoke test).

Do this after **any** change to:

- the public-input order in `main`
- the `holder_binding` / `statement` / `nullifier` / `auditor_blob` formulas in
  `eligibility.nr`
- the Schnorr scheme or the Grumpkin parameters in `corridor-sdk/src/schnorr.ts`

Nonces are derived deterministically (EdDSA-style), so regenerating without a
substantive change produces a byte-identical fixture.

## Why the SDK owns it

The signature must verify in-circuit, which means the SDK's `schnorr.ts` and the
circuit's `noir-lang/schnorr` verifier must agree exactly. `schnorr.ts` is
pinned to that library's test vector, and `nargo execute` on this fixture is the
end-to-end check that they do.
